# Live workspace UX review — 2026-11-08

Scope: repair the signed-in transaction experience against the existing
[sky/pink reference](screenshots/sky-pink-desktop.jpg),
[donut reference](screenshots/donut-trend-desktop.jpg) and
[entry sheet](screenshots/add-transaction-mobile.jpg). Keep the existing stack,
financial RPCs, exact IDR and authorization. No hosted changes or deployment.

Method: screenshot comparison, browser task walkthroughs, keyboard checks and
automated layout assertions using synthetic identities. Real ledger migrations
and SQL/RLS run locally; Auth/HTTP uses the isolated test adapter. No human
participant study or hosted Auth acceptance is claimed.

## Limits

This adapts Taste's hierarchy, spacing, copy and interaction principles to the
existing authenticated finance app and its requested reference. Static marketing
page gates, random palette deals, screen-height sections, hero entrances and
decorative moments are not applied to the ledger. No Taste marketing-gate pass
is claimed.

Overview/Transactions/Accounts links scroll to real sections in the same
workspace. Switching workspaces goes through authorized discovery; it never
switches identity. Budget editing, goals, forecasts and fabricated chart history
remain outside this transaction slice. Category tables preserve negative/unsafe
exact amounts when the existing chart guard declines to draw a pie.

Not checked: human usability study, physical phone/virtual-keyboard behavior,
screen readers, cross-browser matrix, native database concurrency and hosted
Auth/RPC deployment. Existing hosted blockers remain in INTEGRATION_AUDIT.md.
No financial schema/write semantics, migrations, real data or deployment changed.
